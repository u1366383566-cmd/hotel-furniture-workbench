# 全景产品的智能规划

负责人先在「未知保护与系统设置」中配置文本规划模型的服务地址、模型名称和密钥。接口需兼容 `POST /v1/chat/completions`；文本模型与图片模型分别配置。文本密钥留空保存时保留原值，也可使用环境变量 `WORKBENCH_TEXT_API_KEY`。现有系列的一句话创建功能在未配置独立文本服务时仍兼容原有上游。

1. 在系列规则区域选择已有系列，或通过一句风格描述创建并修改系列规则。
2. 新建批次，选择系列，分别填写每个系列的正式款和候补款数量，以及偏好、禁忌、目标和生图预算。创建后不会自动派图。
3. 在「全景初筛区」使用「规划未完成方案」，或逐款生成、重新规划。模型调用失败时已完成的方案会保留，可以重试。逐款修改家具、软装或提示词时，核对提示词与方案一致后保存。
4. 对照每款的相似提醒和历史图片，确认全部正式款与候补款。系统保存确认时的候选和负责人决定；负责人确认预算后，点击「启动首发全景」。
5. 全景就绪后点击「对照与核实」，同时查看当前图和相似款，必要时修正家具特征；该核实记录绑定当前全景版本。后续按既有流程初筛、生成下游三图并终审归档。归档区也可核实特征。
6. 若候补耗尽，追加候补后进入全景初筛区，先规划并确认新增候补；未确认的候补不会自动派图。确认后系统按原有缺口和预算规则补位。

相似提醒按床屏、床体、床头柜和柜体的文字特征进行筛选，范围包含已归档款、本批次方案，以及其他批次已确认且未淘汰的方案。人工核实的成图特征优先于原始方案；缺少核实记录的历史款使用规划记录。文字筛选不能保证识别所有视觉相似款，最终由审核人员判断。它不会自动淘汰方案。

规划模型计数记录收到的成功上游响应；即使响应内容无法解析，服务商也可能收取调用费用，系统会记录这次响应。生图预算仍由既有生图账本单独控制。真实模型的可用性、成本和成图质量取决于实际接入的服务，建议先用少量方案验证。
