# NAS 自动上传部署与恢复

归档事务创建上传任务；历史归档需人工入队。无上传安全检查时任务等待，不会进行网络写入。四图上传后由操作员在 NAS 人工检查并确认，不能把上传请求完成当作远端完整性已验证。

## 启用前置条件

在独立、可清理的测试目录实测当前 WebDAV 连接的目录创建、`If-None-Match: *` 禁止覆盖和冲突处理。网络失败、未知结果或安全语义未通过时不得开启上传。确认地址与 `zhengzhou-nas` 对应的外贸部共享一致。

仅当上述检查通过后，将已有 `zhengzhou-nas` 连接的最小 rclone 配置放入专用 0600 配置文件，授权工作台用户读取；它包含可还原的凭据，应按密码保护，禁止提交到仓库或打印。通过工作台服务的受保护环境配置设置 `WORKBENCH_NAS_RCLONE_CONFIG` 指向该文件，以及 `WORKBENCH_NAS_PUBLISH_VERIFIED=1`。这不是新增 NAS 账号。重启前检查在途生图，并遵循 GitHub 到 90 的发布流程。

## 异常与回滚

每组只由一个持有操作系统锁的后台进程处理。上传前检查四图归档版本、全景依赖、文件格式、尺寸、编号、文件名和文件哈希；上传中断后先查询远端，不覆盖同名文件。四图传输结束后转为“待人工确认”，用户在 NAS 检查后确认。人工确认前不得显示完成；自动重试达到上限后保留失败任务。`nas_upload_settings` 控制自动入队；指定测试组人工确认后才开启并释放等待的归档组。

若需停止网络上传，移除 `WORKBENCH_NAS_PUBLISH_VERIFIED` 后按工作台部署流程重启；已排队任务保留。重启恢复时，原来正在执行的任务会等待重试。每张图直接写入正式产品目录，上传期间目录可能暂时不完整；未知归属或已有不一致文件时停止，禁止覆盖。
