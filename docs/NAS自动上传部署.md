# NAS 自动上传部署与恢复

归档事务创建上传任务；历史归档需人工入队。无安全发布验证时任务保持“等待核验”，不会进行网络写入。服务端状态是实际状态，不等于 NAS 文件已存在。

## 启用前置条件

在独立、可清理的测试目录实测当前 WebDAV 连接的目录创建、`If-None-Match: *` 禁止覆盖、完整读回校验、`MOVE` 的 `Overwrite: F` 及冲突处理。网络失败、未知结果或安全语义未通过时不得开启上传。确认地址与 `zhengzhou-nas` 对应的外贸部共享一致。

仅当上述检查通过后，将已有 `zhengzhou-nas` 连接的最小 rclone 配置放入专用 0600 配置文件，授权工作台用户读取；它包含可还原的凭据，应按密码保护，禁止提交到仓库或打印。通过工作台服务的受保护环境配置设置 `WORKBENCH_NAS_RCLONE_CONFIG` 指向该文件，以及 `WORKBENCH_NAS_PUBLISH_VERIFIED=1`。这不是新增 NAS 账号。重启前检查在途生图，并遵循 GitHub 到 90 的发布流程。

## 异常与回滚

每组只由一个持有操作系统锁的后台进程处理。超时和进程中断会先重新核验远端；目录冲突和内容不一致不会覆盖。自动尝试达到上限后保留失败任务，人工可重试。待核验不等于成功。

若需停止网络上传，移除 `WORKBENCH_NAS_PUBLISH_VERIFIED` 后按工作台部署流程重启；已排队任务保留。重启恢复时，原来正在执行的任务会等待核验。不要人工删除或修改 `.workbench-<任务ID>` 目录，除非核对过该任务和远端状态。
