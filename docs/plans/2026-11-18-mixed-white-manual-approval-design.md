# 四图混合白底版本人工确认设计

## 背景与目标

部分设计完成白底图重做后，当前白底组合图是新版本，但双床和床头近景仍是基于旧白底生成的旧版本。四张图片从人工视觉上可能属于同一系列，家具、材质、配色和空间关系均可接受，继续强制重做会浪费时间与生图额度。

本功能增加一条受控的“人工视觉匹配确认”路径：美工并排检查四图后，可以确认混合白底版本仍可作为同一组交付，直接归档、导出和上传 NAS。系统不得因此取消其他完整性校验，也不得改写图片来源或伪造版本一致性。

## 方案选择

保留三种并存的处理方式：

1. 一键回选旧白底：若双床和局部图共同引用同一张有效旧白底，将当前白底切回旧版本，四图引用重新一致。这是现有能力，仍作为优先快捷路径。
2. 人工视觉匹配确认：保留当前四张图和全部来源记录，由美工明确接受混合白底版本，再执行归档。这是本设计新增的受控覆盖。
3. 重做配图：继续作为严格一致性方案，由美工决定是否消耗额度重新生成双床或局部图。

人工确认只解除“当前白底版本与双床/局部图引用版本不同”这一项业务拦截。图片不存在、损坏、未完成、未知、已失效、全景基准不一致或页面快照过期等问题继续硬拦截。

## 权限与交互

当前登录的美工、负责人和管理员均可直接执行人工确认。视觉判断由美工负责，本操作不创建生图任务、不预占生图额度，也不增加人工重做次数。

四图卡片检测到白底版本不一致且四张图均已完成时，显示次要按钮“四图肉眼匹配，确认归档”。点击后打开专用确认弹窗，并排展示四张图，同时列出：

- 当前整套家具白底版本；
- 双床实际引用的白底版本；
- 床头局部实际引用的白底版本；
- 本次将归档的四个槽位版本 ID。

美工必须勾选“我已并排检查四张图，确认家具、材质、配色和系列气质一致”，并可填写可选的确认说明。未勾选时按钮不可提交。确认过程中版本发生变化时，提示刷新后重新检查，不允许静默换图。

完成确认后，该组使用原“四图合格归档”事务归档。原先禁用的归档按钮不直接开放；混合版本只能通过该确认入口提交，避免误触。批量归档仍只处理普通一致组，混合版本组必须逐组确认。

## 服务端接口与数据

扩展 `POST /api/designs/{design_id}/review_quad` 的归档请求：

```json
{
  "action": "archive",
  "expected_slot_versions": {
    "panorama": "ver_pano",
    "white_isolated": "ver_white_new",
    "twin_bed": "ver_twin",
    "nightstand_closeup": "ver_nightstand"
  },
  "allow_mixed_white_versions": true,
  "visual_approval_note": "四图肉眼检查为同一系列"
}
```

默认 `allow_mixed_white_versions=false`，旧调用行为保持不变。只有归档动作允许该字段为真。

新增 `quad_visual_approvals` 表，表示一组设计的人工视觉覆盖记录：

- `id`、`design_id`、`batch_id`；
- 当前白底版本 ID；
- 双床和床头局部实际引用的白底版本 ID；
- 确认时的四槽位版本快照 JSON；
- 确认说明、操作人、角色和时间；
- `design_id` 唯一，重复归档不得生成多条记录。

不修改双床和局部图的 `prompt_metadata.reference_version_id`，因为该字段记录真实生成来源；人工确认只表示视觉验收结果，不能把旧白底来源伪装成新白底。设计详情接口增加可为空的 `quad_visual_approval` 字段，供已完成列表展示“人工确认混合白底”标识。

## 服务端校验

归档事务继续校验四图槽位完整、快照版本与当前指针一致、图片已完成、文件存在且可解码、预览文件有效、全景依赖一致、设计未归档或淘汰、批次不在异常暂停状态。

当发现当前白底与双床或床头局部图的引用版本不同：

1. 未提交人工确认标志时，返回现有 409，并说明可回选旧白底、人工确认或重做。
2. 提交确认标志时，分别校验两个被引用的旧白底版本属于当前设计、文件有效、未失效，且与当前全景版本一致。
3. 仅当不一致来源限定为双床和床头局部图时允许通过；其他槽位或全景错误继续失败。
4. 归档成功时，在同一个数据库事务中写入 `quad_visual_approvals` 与审计日志，审计动作使用 `archive_quad_with_manual_visual_override`。
5. 重复提交相同确认使用幂等行为：不重复归档计数、不重复增加数组记录、不产生冲突。

## 导出与 NAS

人工确认后的设计按普通已归档组处理。导出和 NAS 上传使用当前四个槽位中的四张图片，不重新生成，也不改变已经分配的产品编号。NAS 仍按 `TFMKxxx` 文件夹保存四张标准 PNG，并在系统侧保留混合白底人工确认记录。

## 验证与发布

- 未确认的混合白底仍被 409 拦截。
- 美工提交正确快照和确认标志后可归档，生图任务数、预算流水和重做次数不增加。
- 操作人权限为美工时允许；伪造或缺失身份仍由现有可信代理机制拦截。
- 当前白底或任一槽位版本变化、快照过期、旧白底文件丢失、旧白底失效、全景依赖不一致时仍失败。
- 重复归档请求保持幂等，分组和审计记录只产生一次。
- Playwright 覆盖四图不一致提示、确认弹窗、未勾选禁用、确认归档、已完成标识和 NAS 入队。
- 本地验收通过后提交并推送 GitHub；90 从 GitHub 拉取同一提交部署，核对服务和实际混合白底组。实际图片是否达到人工视觉标准由美工判断。

## 非目标

- 不自动将混合版本组视为合格。
- 不改变生成、白底重做、全景审核和配图依赖规则。
- 不自动重做图片，不自动消耗额度。
- 不取消图片完整性、版本快照、未知结果、损坏文件和防覆盖保护。
